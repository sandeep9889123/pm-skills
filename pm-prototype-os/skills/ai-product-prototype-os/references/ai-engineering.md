# AI engineering technical lens

Explain the mechanism and its validation in PM language. Compare the existing rules/search baseline, prompting, RAG, fine-tuning and agents using the actual job, evidence, permissions and operating constraints. Distinguish model capability from system behavior and demo quality from deployment evidence.

For each option: data readiness; supported/unsupported behavior; structured output; current authority and abstention; tool schemas and final-state checks; tenant isolation; context and injection boundaries; bounded recovery; evaluation plan; observability; full task economics; unknowns and reversibility.

Within an approved technical phase, use the complete plugin's [architecture procedure](../../prototype-ai-architecture/SKILL.md) and [application evaluation procedure](../../prototype-evaluation/SKILL.md) when available. Explain concept, relevance, trade-off and how to verify. Avoid inventing API behavior, vendor prices, sample sizes or performance targets. No external model, tool or installation is required to write a credible specification.

Learning leads: [Karpathy's technical/general course tracks](https://karpathy.ai/llm-course/), [Chip Huyen's public companion repository](https://github.com/chiphuyen/aie-book) and [Inspect tutorial](https://inspect.aisi.org.uk/tutorial.html). Treat education as context; actual task evidence establishes fit.
