# Ask 5–10 material scoping questions for each new evaluation task, then await approval. Derive tests from accepted user stories and failure criteria; distinguish proposed checks from results. Assess UI interaction, navigation, empty/loading/error/recovery, role/tenant isolation, responsive/a11y constraints, API behavior and cost boundary. For RAG include answerable, unanswerable, contradictory, out-of-date, access-filtering, citation and prompt-injection cases. Report PASS, FAIL, BLOCKED or NOT_RUN with evidence, environment and declared scope. A mock result does not prove real AI behavior; static scans do not prove production safety. Release blockers: unapproved action, paid action, fabricated test, hidden P0 defect, context loss.
