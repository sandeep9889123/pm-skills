# Journey Decomposition

Translate the leading use-case hypothesis into a discovery journey.

## Stage design

Aim for 5-8 stages. Each stage should represent a meaningful workflow, handoff, rule boundary, or decision point.

For each stage define:

- stage objective
- actor(s), if known
- current-state behavior to understand
- input/data dependency
- system/integration dependency
- business rules and exceptions
- handoff / owner
- output
- success condition
- unknowns

Do not invent prospect-specific workflow steps. Use industry patterns only as hypotheses that must be tested.

## Good stage boundaries

Prefer stages where one of these changes:

- actor
- system
- data source
- business rule
- approval
- risk
- commercial commitment
- operational handoff

Avoid slicing a workflow merely to make the diagram look comprehensive.

## Scope discipline

Mark each stage:

`PHASE 1 CANDIDATE | LATER | DEPENDENCY | UNKNOWN`

A future-state capability should not silently become Phase 1 because it sounds strategically attractive.

## Output

A compact stage map that can drive questions, solution options, ownership capture, and scope decisions.
