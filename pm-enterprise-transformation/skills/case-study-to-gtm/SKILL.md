# Case Study to GTM

## Purpose

Turn verified delivery proof into a repeatable selling motion, not a generic case-study page.

Prerequisite: use only claims that survived evidence/confidentiality review. If proof is weak, create a hypothesis-led sales narrative and label it accordingly.

## Method

1. **Identify the transferable mechanism**
   - what customer problem was solved?
   - why did the intervention work?
   - which conditions were necessary?
   - which parts were customer-specific?

2. **Define ICP and buying context**
   - firmographic/operational fit
   - trigger event
   - buyer, champion, users, blockers
   - existing alternative/system of record
   - budget owner and likely buying motion

3. **Translate proof into value**
   Build a chain:
   `pain → operational consequence → solution mechanism → verified proof → buyer outcome`.

   Do not copy a metric into messaging without explaining relevance to the target buyer.

4. **Build sales narrative**
   - 30-second problem/value statement
   - 2-minute proof story
   - discovery questions that test whether the prospect has the same problem
   - qualification/disqualification criteria
   - objection responses with evidence
   - demo storyline tied to buyer outcomes
   - next-step CTA appropriate to maturity: discovery, workshop, pilot, assessment, proposal

5. **Build GTM asset map**
   Recommend only assets justified by the motion:
   - one-page case study
   - solution brief
   - executive email
   - outbound sequence
   - discovery guide
   - battlecard
   - demo script
   - webinar/roundtable
   - landing page
   - pilot offer

6. **Distribution and measurement**
   Define audience, owner, channel, CTA, stage metric, and learning question for each asset.

## Reliability gates

- Never imply that one client proves market-wide demand.
- Never use a client logo/name without clearance.
- Never claim ROI unless cost and benefit assumptions are defensible.
- Do not hide fit constraints that made the success possible.
- Search for evidence that the target ICP differs materially from the reference client.
- If the case is not transferable, recommend `ACCOUNT-SPECIFIC`, not a broader GTM push.

## Output

### GTM package
- verified proof summary
- target ICP and trigger
- positioning statement
- discovery script
- qualification criteria
- proof-led talk track
- objections/evidence
- demo narrative
- asset/distribution plan
- metrics and feedback loop

### Decision
`SCALE GTM | TEST WITH 3-5 PROSPECTS | ACCOUNT-SPECIFIC | NEEDS MORE PROOF`

State what would invalidate transferability.
