# Case Study to GTM

## Purpose

Turn verified delivery proof into a repeatable selling motion, not a generic case-study page.

Prerequisite: use only claims that survived evidence/confidentiality review. If proof is weak, create a hypothesis-led sales narrative and label it accordingly.

## Cross-Skill Lineage Consumer Contract

When client proof includes claim IDs or a `Reliability Handoff`:

- preserve each restated proof claim's ID, state, scope, attribution, and publishability;
- never upgrade `TARGET`, `INFERENCE`, `UNKNOWN`, `ACCEPTED`, or pilot-scoped proof through marketing wording;
- never convert `INTERNAL_SALES_ONLY`, `NEEDS_CLIENT_CLEARANCE`, or other restricted proof into public collateral;
- any claim that the proof transfers to a new ICP/segment is a **new derived claim** with parent proof IDs;
- transferability normally remains `INFERENCE` until tested beyond the reference account;
- anonymization does not strengthen evidence or automatically clear publishability;
- repeated appearance across case study, deck, email, and battlecard is not corroboration;
- unresolved proof/clearance P0s remain visible downstream.

## Method

### 1. Identify the Transferable Mechanism

Ask:
- what customer problem was solved?
- why did the intervention work?
- which conditions were necessary?
- which parts were customer-specific?

Preserve source proof IDs. Create new parent-linked claim IDs only for generalized mechanism/transferability conclusions.

### 2. Define ICP and Buying Context

Assess:
- firmographic/operational fit
- trigger event
- buyer, champion, users, blockers
- existing alternative/system of record
- budget owner and likely buying motion

Do not infer these from the reference client's organization unless evidence supports transferability.

### 3. Translate Proof Into Value

Build:

`pain -> operational consequence -> solution mechanism -> verified proof -> buyer outcome`

Every proof element must link to its original claim ID. The buyer-outcome relevance may be a derived claim and must be labelled accordingly.

Do not copy a metric into messaging without preserving baseline/denominator/period/scope where material.

### 4. Build Sales Narrative

- 30-second problem/value statement
- 2-minute proof story
- discovery questions testing whether the prospect has the same conditions
- qualification/disqualification criteria
- objection responses with evidence claim IDs
- demo storyline tied to buyer outcomes
- next-step CTA appropriate to maturity: discovery, workshop, pilot, assessment, proposal

### 5. Build GTM Asset Map

Recommend only assets justified by proof maturity and publishability:
- one-page case study
- solution brief
- executive email
- outbound sequence
- discovery guide
- battlecard
- demo script
- webinar/roundtable
- landing page
- pilot offer

Do not put a restricted claim into a public asset merely because the client name is removed.

### 6. Distribution and Measurement

Define audience, owner, channel, CTA, stage metric, and learning question for each asset.

## Reliability Gates

- Never imply that one client proves market-wide demand.
- Never use a client logo/name without clearance.
- Never claim ROI unless cost and benefit assumptions are defensible.
- Do not claim broad transferability until tested beyond the reference account.
- Do not hide fit constraints that made the success possible.
- Search for evidence that the target ICP differs materially from the reference client.
- If the case is not transferable, recommend `ACCOUNT-SPECIFIC`, not a broader GTM push.
- Never drop inherited confidentiality, attribution, or scope restrictions during copywriting.

## Output

### GTM Package
- verified proof summary with claim IDs
- target ICP and trigger
- positioning statement
- discovery script
- qualification criteria
- proof-led talk track
- objections/evidence
- demo narrative
- asset/distribution plan
- metrics and feedback loop

### Transferability Ledger

| Derived Claim ID | Parent Proof IDs | Target ICP/Scope | Derivation | State | Evidence Needed |

### Reliability Handoff

```text
Coverage: COMPLETE FOR DECLARED SCOPE | PARTIAL | BLOCKED

### Reused Proof Claims
| Claim ID | Claim | State | Reference Scope | Attribution | Publishability | Allowed Assets |

### Derived GTM Claims
| Claim ID | Parent IDs | Derivation | State | Target Scope | Caveats |

### Unresolved P0
[proof, transferability, buying-context, or clearance blockers]

### Prohibited Interpretations
[client proof != market demand; pilot != production; anonymized != cleared; repeated claim != corroborated]
```

### Decision

`SCALE GTM | TEST WITH 3-5 PROSPECTS | ACCOUNT-SPECIFIC | NEEDS MORE PROOF`

State what would invalidate transferability and which claim IDs would change state if new evidence is obtained.
