# Solution to Sales Playbook

## Purpose

Make an enterprise solution sellable without reducing it to a feature pitch. A playbook should help sales decide who to pursue, what to discover, when to disqualify, what proof to use, and how to hand off a winnable deal.

## Method

1. **Define sellable unit**
   State what is standard, configurable, optional, bespoke, and explicitly unsupported.

2. **Define ICP and anti-ICP**
   Include trigger events, problem severity, technical/operational preconditions, buyer, champion, users, procurement/security complexity, and implementation readiness.

3. **Qualification contract**
   Define evidence required before moving stages:
   - problem and consequence
   - urgency/trigger
   - stakeholder map
   - success criteria
   - data/integration readiness
   - decision process
   - commercial plausibility
   - implementation path

4. **Discovery sequence**
   Ask questions that reveal current workflow, measurable pain, existing alternatives, failed attempts, constraints, desired outcomes, trust requirements, and decision criteria. Do not lead with solution capabilities.

5. **Proof strategy**
   Match proof to buyer risk:
   - reference architecture
   - case study
   - benchmark/evaluation
   - prototype/demo
   - workshop
   - pilot/PoC
   - security/compliance evidence

   Do not run a PoC when a simpler proof can resolve the decision risk.

6. **Demo narrative**
   `customer problem → workflow → key decision/risk → capability → evidence → expected outcome`.
   Avoid feature tours.

7. **Objections and disqualification**
   For price, build-vs-buy, incumbent, security, accuracy, change management, timing, and implementation. State where the competitor/alternative may genuinely be stronger.

8. **Commercial and delivery handoff**
   Capture assumptions sold, scope boundary, dependencies, acceptance criteria, promised outcomes, exclusions, owners, and unresolved risks. Prevent sales-to-delivery promise drift.

## Reliability gates

- no unsupported ROI or competitor claims;
- no “enterprise-ready” label without relevant evidence;
- no stage progression when exit evidence is absent;
- no hiding implementation dependencies to improve conversion;
- no generic playbook if buyer/problem differs materially by segment.

## Output

Produce a one-page rep view plus detailed playbook:
ICP/anti-ICP, discovery, qualification, proof ladder, demo, objections, competitive traps, commercial boundaries, handoff checklist, stage metrics.
